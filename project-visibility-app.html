Visibility dashboard

A dashboard answering how much was being created, and when. Built to a brief during my internship at KYND.

  • React
  • Node.js
  • Express
  • PostgreSQL
  • Chart.js
  • 2023

The brief

The business wanted better visibility into how many records were being created over time, across three related kinds of thing: organisations, reports, and the documents attached to those reports.

KYND supplied the starting point — a PostgreSQL database running in Docker, the three tables, and seeders to populate them with dummy data. Building the API and the interface on top of it was the task.

The API

An Express service talking to Postgres, with an endpoint for each of the three record types.

The useful part is that every endpoint takes the same shape of query: a search term, plus independent date ranges for when a record was created and when it was last updated. That means the interface never needs to filter anything itself — it asks the database for exactly the slice it wants to show, and the same endpoint serves a summary count and a detailed list.

The interface

A React front end built around picking a period and seeing what happened in it. Date-range pickers and a search bar drive the query; the results come back as running totals, donut charts drawn with Chart.js showing how records break down by category, and lists of the matching records underneath.

Changing the range re-queries the API and redraws, so the charts and the lists always describe the same slice of data.

Built against seeded dummy data supplied with the brief, so the numbers it showed were not real. The source is not public.
