Explainability under data augmentation

My MSc dissertation at UCL. Fixing class imbalance with synthetic data makes the numbers better — but does the model still rely on the same things?

  • Python
  • PyTorch
  • SHAP
  • Optuna
  • 2025

The question

When a dataset has far more of one class than another, the usual fix is to manufacture more of the rare one. Whether that worked is normally judged on accuracy or F1 — which tells you the model gets more answers right, but not whether it is getting them right for the same reasons.

This project treats that gap as the thing to measure: does augmentation quietly change what a model pays attention to, and does it matter which augmentation method you pick?

The experiment

Three datasets of deliberately different shape: heart failure prediction (medical, around 900 rows), a personality dataset (around 2,900), and forest cover type (around 580,000 rows, and naturally imbalanced rather than made so).

  • For the balanced datasets, imbalance was introduced on purpose at three severities — roughly 1:10, 1:2 and 1:1 — so any effect could be tracked as the imbalance got worse.
  • Two augmentation methods were compared: SMOTE, which interpolates between existing minority examples, and CTGAN, a GAN trained on the minority class alone to generate new synthetic rows.
  • A control model was trained on the untouched imbalanced data, giving every augmented model something to be compared against.

Measuring the change

Every model is explained with SHAP, which gives a contribution score per feature. Averaging those gives a profile of what that model leans on.

Each augmented model’s profile is then compared against the control’s: feature by feature, and as a single Euclidean distance across the whole feature vector — so “how far has the reasoning moved” reduces to one number that can be compared across methods and severities.

F1 and confusion matrices are tracked alongside, so a shift in explanation can be read next to whether performance actually improved at all.

Making it reproducible

Comparing explanations only means something if the differences come from the augmentation rather than from run-to-run noise, so every random source is seeded — Python, NumPy and PyTorch, with cuDNN pinned to deterministic mode.

  • A small PyTorch network, with Optuna tuning learning rate and batch size rather than leaving them arbitrary.
  • The pipeline is split into preprocessing, augmentation, training and analysis stages, each writing its output to disk.
  • Finished stages are detected and skipped on a rerun, so a run that takes hours does not start from nothing after an interruption.
